<h2 id="adds">What MAF runs. What Tracon adds.</h2>
<p class="lx-adds-lede">MAF is the runtime and stays the runtime. Each row is something the packages add inside the same host. The MAF column paraphrases Microsoft’s documentation, read on 2026-11-15.</p>
<table class="lx-adds-table">
<thead><tr><th scope="col">Concern</th><th scope="col">Microsoft Agent Framework</th><th scope="col">Tracon adds</th></tr></thead>
<tbody>
<tr><th scope="row">The agent</th><td data-label="Microsoft Agent Framework">Executes the agent and its model and tool loop. <code>AIAgent</code>, <code>AgentSession</code>, <code>ChatMessage</code> and <code>AIFunction</code> are its types.</td><td data-label="Tracon adds">Uses those types as they are. Adds a catalog, a definition compiler and a recording layer. <a href="/concepts/">Concepts <span aria-hidden="true">→</span></a></td></tr>
<tr><th scope="row">Run record</th><td data-label="Microsoft Agent Framework">Emits OpenTelemetry traces, logs and metrics to the backend you choose. The pages describe no built-in store of runs, tool calls or cost.</td><td data-label="Tracon adds">Persists each run: events, tool calls, timings and cost in PostgreSQL, SQL Server or SQLite. <div class="lx-ch-text">
<p class="lx-ch-label"><span>03 / Recover</span> {clock.decided}</p>
<h3 id="recover-q">What survives a restart?</h3>
<p class="lx-readback">The hold. The decision later opens <code>R2</code>.</p>
<Snippet name="persistence" />
</div>
<div class="lx-ch-side">
<p>At {clock.restart} the host restarts; the held run and the pending call are rows in PostgreSQL. After the restart, {sample.actor} rejects the call. The audit entry is written first, and the decision applies only if that write succeeds.</p>
<p>The decision opens R2 in session <code>{sample.session}</code>, where the model reads the refusal. R1 keeps its status: run history is append-only. A client that lost the <code>202</code> retries with the same <code>Idempotency-Key</code> and gets the stored response.</p>

<p class="lx-ch-label"><span>04 / Record</span> {clock.completed}</p>
<h3 id="record-q">What happened, and who changed what?</h3>
<p class="lx-readback"><code>{verify.status}</code> · audit trail, {verify.entriesChecked} entries checked</p>

<h2 id="asked">Questions before production.</h2>
<div class="lx-asked-grid">
<div class="lx-asked-item">
<h3>What does it add to a request?</h3>
<p>No overhead figure against bare MAF is published, so none is stated here. What is measured is one machine with a synthetic model: three request paths, their latency percentiles and the rows each run writes. Recording runs inline, so a slow event sink adds its latency to every event, and a failing one is switched off for that run. That is not an SLA.</p>
<p class="lx-more"><a href="/guides/production/#what-one-environment-measured">What one environment measured <span aria-hidden="true">→</span></a></p>
</div>
<div class="lx-asked-item">
<h3>What happens when the store is unavailable?</h3>
<p>Three behaviors, on purpose. Run recording fails quietly: the recorder switches itself off for that run, logs, and the run continues. Reads and queue operations fail loudly: they raise the provider’s exception and never return an empty list. Workers stay up and retry on the next tick. A store failure costs the record, not the run. Work in flight when the database goes away is lost the way a crash loses it, and becomes leasable again when its lease expires.</p>
<p class="lx-more"><a href="/guides/production/#the-database-is-unreachable">The database is unreachable <span aria-hidden="true">→</span></a></p>
</div>
<div class="lx-asked-item">
<h3>How is it different from DevUI or Microsoft’s control planes?</h3>
<p>DevUI is, in Microsoft’s words, “a sample app”. Foundry Control Plane, Agent 365 and Entra Agent ID are services Microsoft runs. Tracon is a library in your own host and a control plane for that one host: it keeps no registry of a company’s agents and issues no agent identity. Tracon is not a Microsoft product, and no Microsoft product certifies it.</p>
<p class="lx-more"><a href="/getting-started/microsoft-control-planes/">Microsoft’s control planes <span aria-hidden="true">→</span></a></p>
</div>
<div class="lx-asked-item">
<h3>I already export traces. Why this?</h3>
<p>Keep the backend. Tracon emits OpenTelemetry spans and a meter, and you choose the exporter. A trace backend shows what happened. Tracon also acts: it holds a tool call for approval, scopes queries to a tenant, and keeps the audit chain.</p>
<p class="lx-more"><a href="/guides/observability/">Observability and cost <span aria-hidden="true">→</span></a></p>
</div>
<div class="lx-asked-item">
<h3>What is the license?</h3>
<p>Every package is MIT, and so is <code>@tracon/client</code> on npm. There is no license key, no activation call and no feature gate. Earlier previews were published under other terms, and a published version keeps the terms it shipped with.</p>
<p class="lx-more"><a href="/reference/licensing/">Licensing <span aria-hidden="true">→</span></a></p>
</div>
<div class="lx-asked-item">
<h3>What does it need to run?</h3>
<p>An ASP.NET Core host on .NET 10. Runtime packages target <code>net10.0</code> only. The packages are preview, and the public API is not frozen.</p>
<p class="lx-more"><a href="/reference/compatibility/">Compatibility <span aria-hidden="true">→</span></a></p>
</div>
