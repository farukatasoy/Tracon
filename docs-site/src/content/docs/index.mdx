<h3 id="separate-q">Who owns this request?</h3>
<p class="lx-readback"><code>{sample.tenant}</code> · matched by the API key</p>
<p>The request carries an API key bound to tenant acme, and the key outranks any claim or header. From here on, tenant-scoped queries keep each tenant's records logically isolated. Your host signs operators in; Tracon reads their <code>tenant_id</code> claim, and once a claim type is set, it never reads the header.</p>

<p class="lx-ch-label"><span>02 / Clear</span> {clock.held}</p>
<h3 id="clear-q">Who may call this tool?</h3>
<p class="lx-readback">No one yet. <code>AwaitingApproval</code></p>
<p>The policy is set in code, not by the model. The tool requires approval, so the queued run closes <code>AwaitingApproval</code> and the call waits with its arguments, for 24 hours by default. A tool is a method: the console can select it but never write it.</p>

<div class="lx-ch-text">
<p class="lx-ch-label"><span>03 / Recover</span> {clock.decided}</p>
<h3 id="recover-q">What survives a restart?</h3>
<p class="lx-readback">The hold. The decision later opens <code>R2</code>.</p>
<Snippet name="persistence" />
</div>
<div class="lx-ch-side">
<p>At {clock.restart} the host restarts; the held run and the pending call are rows in PostgreSQL. After the restart, {sample.actor} rejects the call. The audit entry is written first, and the decision applies only if that write succeeds.</p>
<p>The decision opens R2 in session <code>{sample.session}</code>, where the model reads the refusal. R1 keeps its status: run history is append-only. A client that lost the <code>202</code> retries with the same <code>Idempotency-Key</code> and gets the stored response.</p>

<div class="lx-ch-text">
<p class="lx-ch-label"><span>04 / Record</span> {clock.completed}</p>
<h3 id="record-q">What happened, and who changed what?</h3>
<p class="lx-readback"><code>{verify.status}</code> · audit trail, {verify.entriesChecked} entries checked</p>
<p>Each run is a numbered event tape: sequence numbers start at 0, leave no gaps, and resume after <code>Last-Event-ID</code> when a stream drops. These are persisted run records. Recording is best-effort, so a store failure costs the record, not the run.</p>
<p class="lx-more"><a href="/concepts/runs/">Read a recorded run <span aria-hidden="true">→</span></a></p>
