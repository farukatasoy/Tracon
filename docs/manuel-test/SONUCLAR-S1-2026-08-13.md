## HATA-S1-004 — `InvariantGlobalization=true` SQL Server kalıcılığını tamamen kırıyor

| | |
|---|---|
| **Önem** | **Kritik** |
| **Durum** | ✅ **ÇÖZÜLDÜ** — karar `K-392`, commit `aa64bc7` (`docs/manuel-test`) |
| **Case** | `MT-SQL-014`, `015`, `024`, `025`, `026`, `027` (6 case bloklanmıştı, düzeltmeden sonra hepsi koşuldu) |
| **Alan** | Örnek uygulama + **paket şablonu** |
| **İlgili faz** | Faz 23 |

**Belirti**
`UseSqlServer()` yapılandırıldığında uygulama hiç açılmıyor. Süreç
`Hosting failed to start` + `Unhandled exception` yazıp sonlanıyor;
`Now listening` hiç yazılmıyor.

```
fail: Microsoft.Extensions.Hosting.Internal.Host[11]
      Hosting failed to start
      System.NotSupportedException: Globalization Invariant Mode is not supported.
         at Microsoft.Data.SqlClient.SqlConnection.TryOpen(TaskCompletionSource`1 retry, SqlConnectionOverrides overrides)
         at Microsoft.Data.SqlClient.SqlConnection.InternalOpenAsync(SqlConnectionOverrides overrides, CancellationToken cancellationToken)
         at System.Data.Common.DbDataSource.OpenDbConnectionAsync(CancellationToken cancellationToken)
```

**Kök neden**
`samples/AgentPrism.Api/AgentPrism.Api.csproj:6` →
`<InvariantGlobalization>true</InvariantGlobalization>`. Bu ayar derlenmiş
`AgentPrism.Api.runtimeconfig.json` içine
`"System.Globalization.Invariant": true` olarak geçiyor.
`Microsoft.Data.SqlClient` Globalization Invariant Mode'u **desteklemez** ve
`SqlConnection.Open` çağrısında koşulsuz `NotSupportedException` fırlatır.

**Neden Kritik — örnekle sınırlı değil**
Aynı ayar paket şablonunda da var:
`src/AgentPrism.Templates/content/AgentPrism.Starter/AgentPrism.Starter.csproj:9`.
`dotnet new` ile proje kuran ve `UseSqlServer()` çağıran **her tüketici** bu
duvara çarpar. AgentPrism bir NuGet paket ailesidir; şablon kusuru doğrudan
tüketiciye taşınır. `AgentPrism.SqlServer` paketi, kendi şablonuyla kurulan bir
projede kullanılamaz durumdadır.

**Kanıt / ayırt edici kontrol**
- Geçerli bağlantı dizesiyle (port 51433, `AgentPrism_S1` mevcut): açılmadı.
- Geçersiz host'la (port 1): **aynı** istisna — yani hata bağlantı hedefine
  bağlı değil, `SqlConnection.Open`'ın kendisinde.
- `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=0` ortam değişkeni **işe yaramıyor**:
  `runtimeconfig.json` içindeki `configProperties` ortam değişkenini ezer.
- SQLite ve bellek içi izlekler etkilenmiyor; `Microsoft.Data.Sqlite` bu moda
  bağımlı değil.
- Ayar doğrulamasıyla kapanan SQL Server case'leri (`011`, `012`, `013`, `016`)
  bağlantıya hiç ulaşmadıkları için normal koştu ve geçti.

**Uygulanan düzeltme** (kullanıcı kararıyla koşum sırasında kodlandı)
`InvariantGlobalization` hem `samples/AgentPrism.Api/AgentPrism.Api.csproj`
hem `src/AgentPrism.Templates/content/AgentPrism.Starter/AgentPrism.Starter.csproj`
dosyasından kaldırıldı. İki dosyaya da ayarın NEDEN açılmadığını yazan bir
yorum bırakıldı ki sonraki oturum geri eklemesin. Karar `K-392` olarak
`docs/KARARLAR.md`'ye yazıldı.

Ayarın kayıtlı bir gerekçesi yoktu (karar defterinde hiç geçmiyordu); ICU
bağımlılığından kaçınma amacıyla konmuş olmalı — doğruluk bu kazancı yener.

**Doğrulama**
- Dört kapı yeşil: `build` 0 uyarı/0 hata · `dotnet test` tüm paketler 0
  başarısız · `pack` exit 0 (85 `.nupkg`) · `format` exit 0.
- İlk denemede `AgentPrism.Templates.Tests` 3/10 kaldı: eklediğim XML yorumu
  `--UseSqlServer` içeriyordu, XML yorumları `--` taşıyamaz (`MSB4025`).
  Yorum düzeltildi, 10/10 geçti. Şablon testleri kusuru yakaladı.
- Derlenmiş `AgentPrism.Api.runtimeconfig.json` artık
  `System.Globalization.Invariant` anahtarını hiç taşımıyor.
- Bloklanan 6 case gerçek SQL Server bağlantısıyla yeniden koşuldu:
  5'i geçti, `MT-SQL-014` `HATA-S1-002`'yi SQL Server'da da doğruladı.

## HATA-S1-002 — `AutoApplyMigrations=false` + hazır olmayan şema uygulamayı kapatıyor

| | |
|---|---|
| **Önem** | Yüksek |
| **Durum** | ⛔ Açık — düzeltilmedi (KOSUM-PLANI §8 toplama oturumuna kaldı) |
| **Case** | `MT-SQL-004` (SQLite) **ve** `MT-SQL-014` (SQL Server) — ikisi de koşuldu ve kaldı |
| **Alan** | `AgentPrism.Sql.Shared` + `AgentPrism.AspNetCore` |
| **İlgili faz** | Faz 23/24, Faz 42 |

**Belirti**
`AutoApplyMigrations=false` ve şema henüz kurulmamışken uygulama açılıyor
(`Now listening` yazıyor), hemen ardından **kendini kapatıyor**. `/health`
isteği bağlantı kuramıyor (`HTTP:000`).

```
crit: AgentPrism.A2AApprovalGuardFilter[0]
      A2A disa acik yuzey denetimi basarisiz oldu; uygulama durduruluyor.
      Microsoft.Data.Sqlite.SqliteException: SQLite Error 1: 'no such table: agentprism_agent_definitions'.
         at AgentPrism.A2AApprovalGuardFilter.RunCheckAsync(...) A2A/A2AApprovalGuardFilter.cs:58
crit: AgentPrism.McpApprovalGuardFilter[0]
      MCP disa acik yuzey denetimi basarisiz oldu; uygulama durduruluyor.
         at AgentPrism.McpApprovalGuardFilter.RunCheckAsync(...) McpServer/McpApprovalGuardFilter.cs:86
```

**Kök neden**
`MigrationHostedService.StartAsync`, `AutoApplyMigrations` kapalıyken
`SchemaReadyGate.MarkReady()` çağırır — bu **bilinçli** bir karardır
("semanin hazir olmasi tuketicinin sorumlulugundadir"). Ancak `SchemaReadyGate`
"migration'lar bitti" ile "şema gerçekten hazır" arasında ayrım yapmaz.
`A2AApprovalGuardFilter` ve `McpApprovalGuardFilter` kapıyı bekler ve açılır
açılmaz `catalog.ListAsync` ile `agent_definitions` sorgular. Şema yoksa sorgu
patlar, `catch (Exception)` bloğu
`lifetime.ApplicationStarted.Register(lifetime.StopApplication)` çağırır.

**Etkisi**
Dokümante edilen sözleşme erişilemez hâle geliyor: `AutoApplyMigrations=false`
kurulumunda operatörün "migration'lar bekliyor" durumunu görmesi için
tasarlanmış `/health` → `Unhealthy` + `pendingMigrations` sinyali hiç
okunamıyor. Yerine kök nedeni gizleyen bir "no such table" kapanma döngüsü
oluşuyor. İlk kurulumda ya da migration adımı sırayı kaçırdığında tam olarak bu
yaşanır.

**Ayırt edici kontrol**
Şema önce `AutoApplyMigrations=true` ile kurulup (45 tablo) sonra `false` ile
açıldığında uygulama sorunsuz ayakta kaldı (`Application is shutting down`
satırı yok, `/health` → `Degraded`). Kusur ayarda değil, **kapının hazır
olmayan şema üzerinde açılmasında**.

**İki sağlayıcıda doğrulandı**
`HATA-S1-004` düzeltildikten sonra `MT-SQL-014` SQL Server'da yeniden koşuldu
ve SQLite ile **birebir aynı** davranışı verdi: `Now listening` → `crit:
AgentPrism.A2AApprovalGuardFilter` → `SqlException: Invalid object name
'agentprism.agent_definitions'.` → `Application is shutting down`,
`/health` `HTTP:000`, şema tablo sayısı 0. Kök nedenin sağlayıcıdan bağımsız
(`AgentPrism.Sql.Shared`) olduğu artık tahmin değil, ölçüm.

**Önerilen düzeltme**
İki yoldan biri: (a) onay denetimleri şema hazır değilken `crit` + kapatma
yerine uyarı verip denetimi ertelesin — sağlık ucu zaten durumu bildiriyor;
(b) `SchemaReadyGate` "hazır" ile "atlandı" durumlarını ayırsın ve bekleyenler
atlandı durumunda SQL'e dokunmasın. (a) daha küçük ve gözlemlenebilirlik
kuralına ("depo hatası çalıştırmayı kesmez") daha yakın.

## HATA-S1-003 — `Data Source=:memory:` dokümante edildiği hâlde hiç çalışmıyor

| | |
|---|---|
| **Önem** | Yüksek |
| **Case** | `MT-SQL-005` |
| **Alan** | `AgentPrism.Sqlite` — public API XML dokümanı |
| **İlgili faz** | Faz 24 |

**Belirti**
`AgentPrism:Sqlite:ConnectionString` = `Data Source=:memory:` ile uygulama
açılmıyor. Migration'lar uygulanıyor, hemen ardından süreç ölüyor.

```
info: AgentPrism.MigrationRunner[0]
      AgentPrism 15 migration uyguladi. Sema: agentprism_.
fail: Microsoft.Extensions.Hosting.Internal.Host[11]
      Hosting failed to start
      Microsoft.Data.Sqlite.SqliteException: SQLite Error 1: 'no such table: agentprism_tenants'.
```

**Kök neden**
`src/AgentPrism.Sqlite/Internal/SqliteDataSource.cs:44` —
`CreateDbConnection()` her çağrıda **yeni** bir `SqliteConnection` üretir.
Çıplak `:memory:` veritabanı **bağlantıya özeldir**: `MigrationRunner` kendi
bağlantısında 15 migration uygular, bağlantı kapanır, veritabanı yok olur.
`EnsureDefaultTenantAsync` yeni bir bağlantı açar — boş bir in-memory
veritabanı — ve `agentprism_tenants` orada yoktur.

**Sözleşme ihlali**
`src/AgentPrism.Sqlite/AgentPrismSqliteOptions.cs:17-18` XML dokümanı:
`Data Source=:memory: desteklenir ama kalici DEGILDIR: baglanti kapaninca veri
gider.` Bu iddia yanlış — `:memory:` hiç desteklenmiyor, uygulama açılmıyor.
XML dokümanı tüketiciye IntelliSense'te gösterilir; paket ailesinin public
sözleşmesinin parçasıdır.

**Doğrulanan çalışan biçim**
`Data Source=file:apmem?mode=memory&cache=shared` ile uygulama sorunsuz açıldı
(15 migration, `/health` → HTTP 200). Paylaşımlı önbellek aynı süreçteki tüm
bağlantılara tek bir in-memory veritabanı verir.

**Önerilen düzeltme**
XML dokümanı `cache=shared` biçimini önersin ve çıplak `:memory:`'nin bir
`DbDataSource` ile çalışmayacağını açıkça yazsın. Alternatif olarak
`AgentPrismSqliteOptionsValidator` çıplak `:memory:`'yi anlaşılır bir mesajla
reddetsin — sessizce "no such table" ile ölmekten iyidir.

## HATA-S1-001 — Koşum hijyeni: `user-secrets` temizliği uygulanmamış

| | |
|---|---|
| **Önem** | Düşük (süreç kusuru, ürün kusuru DEĞİL) |
| **Case** | `MT-SQL-002` |

Şerit açılırken paylaşılan `user-secrets` deposu
`AgentPrism:Sqlite:TablePrefix` = `x_; DROP TABLE agentprism_tenants;--`
taşıyordu — `MT-SQL-002` 3. adımının temizliği önceki oturumda uygulanmamış.
Depo `UserSecretsId=agentprism-sample-api` ile makine genelinde tek olduğu için
bu değer **her şeridi** etkiler ve uygulamanın açılmasını engeller.

KOSUM-PLANI §2.2 gereği depoya yazılmadı. Şerit kendi ayar anahtarlarını ortam
değişkeniyle sabitleyerek ilerledi.

**Öneri:** Toplama oturumunda (KOSUM-PLANI §8) depo temizlenmeli:
`dotnet user-secrets remove "AgentPrism:Sqlite:TablePrefix"`. Ayrıca senaryo
dosyalarındaki "Temizlik" adımlarının koşum sırasında gerçekten uygulanması
gerekir; uygulanmayan temizlik sonraki oturumu bozuyor.
