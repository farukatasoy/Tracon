## HATA-S3-001 — `OpenAIProviderOptions.Endpoint` geçersiz (göreli) değer sessizce elenir, doğrulayıcıya hiç ulaşmaz

- **Case:** MT-OAI-010
- **Önem:** Orta
- **İzlek:** B
- **Ortam:** macOS arm64 · net10 · PostgreSQL · OpenAI

**Beklenen**
`AgentPrism:Providers:OpenAI:Endpoint` göreli (mutlak olmayan) bir değer
taşırsa uygulama `OptionsValidationException` ile başlamayı reddeder.

**Gerçekleşen**
Uygulama sorunsuz başladı, `/api/models` normal yanıt verdi;
`OptionsValidationException` hiç fırlatılmadı.

**Kök neden**
`src/AgentPrism.OpenAI/OpenAIProviderExtensions.cs:164-168`, `Bind()`:

```csharp
if (section[nameof(OpenAIProviderOptions.Endpoint)] is { Length: > 0 } endpoint
    && Uri.TryCreate(endpoint, UriKind.Absolute, out var endpointUri))
{
    options.Endpoint = endpointUri;
}
```

`Uri.TryCreate(..., UriKind.Absolute, ...)` göreli bir dizgi için `false`
döner; bu durumda `options.Endpoint` HİÇ ATANMAZ ve varsayılanında kalır.
`OpenAIProviderOptionsValidator.cs:56`'daki `options.Endpoint is {
IsAbsoluteUri: false }` denetimi bu yüzden varsayılan (adsız) `openai`
sağlayıcısı için **asla tetiklenemez** — geçersiz değer doğrulayıcıya
ulaşmadan `Bind()` içinde sessizce elenir. Bu, `OpenAIProviderOptionsValidator`'ın
kendi XML belgesinin önlemeyi amaçladığı senaryonun ("Bos birakilirsa istek
sessizce resmi OpenAI adresine giderdi") bir varyasyonu: boş değil, GEÇERSİZ
bir değer de aynı sessiz düşüşe uğruyor.

**Yeniden üretme**
1. `export AgentPrism__Providers__OpenAI__Endpoint="sadece-bir-yol"`
2. `dotnet run --project samples/AgentPrism.Api`
3. Uygulama başlar, çökmez.

**Kanıt**
- `/tmp/ap-s3.log`: `Now listening on: http://localhost:5083` (çökme yok)
- Kaynak: `OpenAIProviderExtensions.cs:164-168`, `OpenAIProviderOptionsValidator.cs:56`

**Kapsam**
Yalnız MT-OAI-010'u değil, `OpenAIProviderOptionsValidator`'ın
`IsAbsoluteUri: false` dalının TAMAMINI etkiler — bu dal, standart
`UseOpenAI(IConfiguration)` / `UseOpenAICompatible(ad, IConfiguration)`
yapılandırma yoluyla asla ulaşılamaz ölü koddur. Yalnızca kod tabanlı
`UseOpenAI(o => o.Endpoint = new Uri("...", UriKind.Relative))` gibi bir
kullanım bu denetimi tetikleyebilir.

## HATA-S3-002 — Boş `Models[i].Name` girdisi `BindModels()` içinde sessizce atlanır, doğrulayıcıya hiç ulaşmaz

- **Case:** MT-OAI-012
- **Önem:** Orta
- **İzlek:** B
- **Ortam:** macOS arm64 · net10 · PostgreSQL · OpenAI

**Beklenen**
`appsettings.json`'daki `Models` dizisine `Name` alanı boş bir girdi
eklenirse uygulama `OptionsValidationException` ile başlamayı reddeder.

**Gerçekleşen**
Uygulama sorunsuz başladı; `OptionsValidationException` hiç fırlatılmadı.

**Kök neden**
`src/AgentPrism.OpenAI/OpenAIProviderExtensions.cs:191-198`, `BindModels()`:

```csharp
if (child[nameof(ModelDescriptor.Name)] is not { Length: > 0 } name)
{
    continue;
}
```

Boş (veya eksik) `Name` alanı taşıyan bir model girdisi `options.Models`
listesine hiç eklenmiyor — sessizce atlanıyor.
`OpenAIProviderOptionsValidator.cs:70-78`'deki `Models[index]` boş-isim
döngüsü bu yüzden asla boş isimli bir öge görmüyor; bu doğrulama dalı da
HATA-S3-001 ile aynı ailede ölü koddur.

**Yeniden üretme**
1. `samples/AgentPrism.Api/appsettings.json`'daki `Providers:OpenAI:Models`
   dizisine `{"Name": ""}` ekle.
2. `dotnet run --project samples/AgentPrism.Api`
3. Uygulama başlar, çökmez.

**Kanıt**
- Kaynak: `OpenAIProviderExtensions.cs:191-198`, `OpenAIProviderOptionsValidator.cs:70-78`

**Kapsam**
Aynı `Bind()`/`BindModels()` mantığı `OpenAICompatibleProviderExtensions.cs`
tarafından adlandırılmış (`UseOpenAICompatible`) sağlayıcılar için de
paylaşılıyor (bkz. `OpenAIProviderExtensions.cs:152` XML belgesi: "internal:
OpenAICompatibleProviderExtensions ayni baglama mantigini... kullanir") —
bu yüzden aynı sessiz-eleme muhtemelen adlandırılmış sağlayıcılarda da
geçerlidir; bu oturumda doğrulanmadı (kapsam dışı, `06-SAGLAYICI-DIGER.md`
Azure/adlandırılmış sağlayıcı case'lerinde tekrar gözlenebilir).
