## HATA-S3-001 — `OpenAIProviderOptions.Endpoint` geçersiz (göreli) değer sessizce elenir, doğrulayıcıya hiç ulaşmaz

- **Case:** MT-OAI-010
- **Önem:** Orta
- **İzlek:** B
- **Ortam:** macOS arm64 · net10 · PostgreSQL · OpenAI

**Beklenen**
`AgentPrism:Providers:OpenAI:Endpoint` göreli (mutlak olmayan) bir değer
taşırsa uygulama `OptionsValidationException` ile başlamayı reddeder.

**Gerçekleşen**
Uygulama sorunsuz başladı, `/api/models` normal yanıt verdi;
`OptionsValidationException` hiç fırlatılmadı.

**Kök neden**
`src/AgentPrism.OpenAI/OpenAIProviderExtensions.cs:164-168`, `Bind()`:

```csharp
if (section[nameof(OpenAIProviderOptions.Endpoint)] is { Length: > 0 } endpoint
    && Uri.TryCreate(endpoint, UriKind.Absolute, out var endpointUri))
{
    options.Endpoint = endpointUri;
}
```

`Uri.TryCreate(..., UriKind.Absolute, ...)` göreli bir dizgi için `false`
döner; bu durumda `options.Endpoint` HİÇ ATANMAZ ve varsayılanında kalır.
`OpenAIProviderOptionsValidator.cs:56`'daki `options.Endpoint is {
IsAbsoluteUri: false }` denetimi bu yüzden varsayılan (adsız) `openai`
sağlayıcısı için **asla tetiklenemez** — geçersiz değer doğrulayıcıya
ulaşmadan `Bind()` içinde sessizce elenir. Bu, `OpenAIProviderOptionsValidator`'ın
kendi XML belgesinin önlemeyi amaçladığı senaryonun ("Bos birakilirsa istek
sessizce resmi OpenAI adresine giderdi") bir varyasyonu: boş değil, GEÇERSİZ
bir değer de aynı sessiz düşüşe uğruyor.

**Yeniden üretme**
1. `export AgentPrism__Providers__OpenAI__Endpoint="sadece-bir-yol"`
2. `dotnet run --project samples/AgentPrism.Api`
3. Uygulama başlar, çökmez.

**Kanıt**
- `/tmp/ap-s3.log`: `Now listening on: http://localhost:5083` (çökme yok)
- Kaynak: `OpenAIProviderExtensions.cs:164-168`, `OpenAIProviderOptionsValidator.cs:56`

**Kapsam**
Yalnız MT-OAI-010'u değil, `OpenAIProviderOptionsValidator`'ın
`IsAbsoluteUri: false` dalının TAMAMINI etkiler — bu dal, standart
`UseOpenAI(IConfiguration)` / `UseOpenAICompatible(ad, IConfiguration)`
yapılandırma yoluyla asla ulaşılamaz ölü koddur. Yalnızca kod tabanlı
`UseOpenAI(o => o.Endpoint = new Uri("...", UriKind.Relative))` gibi bir
kullanım bu denetimi tetikleyebilir.

## HATA-S3-002 — Boş `Models[i].Name` girdisi `BindModels()` içinde sessizce atlanır, doğrulayıcıya hiç ulaşmaz

- **Case:** MT-OAI-012
- **Önem:** Orta
- **İzlek:** B
- **Ortam:** macOS arm64 · net10 · PostgreSQL · OpenAI

**Beklenen**
`appsettings.json`'daki `Models` dizisine `Name` alanı boş bir girdi
eklenirse uygulama `OptionsValidationException` ile başlamayı reddeder.

**Kök neden**
`src/AgentPrism.OpenAI/OpenAIProviderExtensions.cs:191-198`, `BindModels()`:


**Kapsam**
Aynı `Bind()`/`BindModels()` mantığı `OpenAICompatibleProviderExtensions.cs`
tarafından adlandırılmış (`UseOpenAICompatible`) sağlayıcılar için de
paylaşılıyor (bkz. `OpenAIProviderExtensions.cs:152` XML belgesi: "internal:
OpenAICompatibleProviderExtensions ayni baglama mantigini... kullanir") —

deseni:

```csharp
if (section[nameof(GoogleProviderOptions.Endpoint)] is { Length: > 0 } endpoint
    && Uri.TryCreate(endpoint, UriKind.Absolute, out var endpointUri))
{
    options.Endpoint = endpointUri;
}
```

`Uri.TryCreate(..., UriKind.Absolute, ...)` göreli bir dizgi için `false`

kaynak karşılaştırması Anthropic'in de aynı riski taşıdığını gösteriyor).

3. Uygulama başlar, çökmez.

**Kapsam**
`HATA-S3-001` ile aynı kök neden ailesi — üç sağlayıcı paketi (`OpenAI`,

açık bir `OptionsValidationException` fırlatan paylaşılan bir yardımcı)
üçünü birden kapatabilir.

## HATA-S3-005 — Akışsız (`Idempotency-Key`) `run` ucu, sağlayıcı SDK istisnalarını yakalamıyor; bare `500` üretiyor (K-296 düzeltmesi eksik uygulandı)

- **Case:** MT-GUARD-023
- **Önem:** Yüksek
- **İzlek:** B
- **Ortam:** macOS arm64 · net10 · PostgreSQL · OpenAI

**Beklenen**
Katalogda olmayan bir OpenAI modeliyle akışsız (`Idempotency-Key` başlıklı)
`run` çağrısı, sağlayıcıdan kaynaklanan bir hata ile (dokümanın öngördüğü
gibi tipik olarak `502 Bad Gateway`, yapılandırılmış ProblemDetails
gövdesiyle) sonuçlanır — bir istisna sızıntısı olmaz.

**Gerçekleşen**
`HTTP/1.1 500`, gövde `{"title":"An error occurred while processing your
request.","status":500}` — `detail` alanı **yok**, hiçbir AgentPrism
ProblemDetails yapısı taşımıyor. Konsolda `Unhandled exception` günlüğü:
`System.ClientModel.ClientResultException: HTTP 404 (invalid_request_error:
model_not_found)`.

**Kök neden**
`src/AgentPrism.AspNetCore/Endpoints/AgentEndpoints.cs`, `AgentRunStream.
ExecuteBufferedAsync` (akışsız/`Idempotency-Key` yolu):

```csharp
catch (Exception ex) when (ex is AgentPrismException or InvalidOperationException or HttpRequestException)
{
    await Results.Problem(title: "Agent calistirilamadi", detail: ex.Message,
        statusCode: StatusCodes.Status502BadGateway).ExecuteAsync(httpContext)...
}
```

Bu, **2026-08-10'dan ÖNCEKİ**, `ExecuteStreamingAsync`'in K-296 ile
düzeltilmeden önce taşıdığı BİREBİR AYNI dar filtredir (bkz. bu dosyanın
S1 notu, `ExecuteStreamingAsync`'teki güncel kod: "🚨 K-296: ... Dar bir
`when` filtresi ... gerçek saglayici SDK istisnalarini ... yakalamadan
kacirirdi"). `ExecuteStreamingAsync` artık HER istisnayı yakalayan genel
bir `catch (Exception ex)` bloğu taşıyor (SSE `error` çerçevesi üretir);
`ExecuteBufferedAsync` bu düzeltmeyi **hiç almamış** — hâlâ eski dar
filtreyi taşıyor. `System.ClientModel.ClientResultException` (OpenAI SDK)
`AgentPrismException`, `InvalidOperationException` ya da
`HttpRequestException`'ın hiçbirinden türemediği için filtre onu
yakalamıyor, istisna ASP.NET Core'un varsayılan işleyicisine düşüyor.

**Yeniden üretme**
1. `POST /api/agents` ile katalogda olmayan bir OpenAI modeli tanımla.
2. `POST /api/agents/{name}/run` çağrısını `Idempotency-Key` başlığıyla
   (akışsız) yap.
3. `HTTP 500`, boş `detail` gözlenir; konsolda `ClientResultException`
   günlüğü görülür.

**Kanıt**
- `/tmp/ap-s3-s4.log`: `System.ClientModel.ClientResultException: HTTP 404
  (invalid_request_error: model_not_found)`
- Kaynak: `AgentEndpoints.cs`, `ExecuteBufferedAsync` ile
  `ExecuteStreamingAsync`'in `catch` blokları karşılaştırıldı.

**Kapsam**
Yalnız OpenAI'yi değil — `AnthropicApiException` de `Exception`'dan
doğrudan türediği için (MT-PROV-036/042'de ölçüldü) aynı boşluğa düşer;
Google'ın `ClientError`si `HttpRequestException`'dan türediği için
(MT-PROV-053) bu özel durumda YAKALANIR, ama bu bir tasarım değil
tesadüftür. Düzeltme: `ExecuteStreamingAsync`'teki genel `catch
(Exception ex)` deseni `ExecuteBufferedAsync`'e de uygulanmalı (yalnız
`AgentPrismContentBlockedException`'ın kendi özel dalı korunarak).
